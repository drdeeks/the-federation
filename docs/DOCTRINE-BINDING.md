# DOCTRINE BINDING — The Federation

This document binds The Federation repository to its universal working
constitution. It is not a second product source of truth.

## Sources

- `docs/FOREVER_DOCTRINE.yaml` — universal integrity and operating principles.
- `docs/FEDERATION-CONCEPT.md` — Federation product meaning and civilization.
- `docs/BUILD_SCOPE.md` — current implementable foundation slice.
- `AGENTS.md` — repository boundaries and change workflow.

The doctrine governs how work is performed. It does not define Federation
features or override the owner's Federation concept.

## Policy mapping

| Principle | Federation application |
|---|---|
| Singular source of truth | One owner for concept, scope, integration facts, code, and submission prose. |
| Self-resolving context | No absolute runtime paths or hidden environment assumptions. |
| Layered, never silently rewritten | New capabilities are additive and reversible; preserve existing work. |
| Fail closed and tamper evident | Unsafe ambiguity blocks consequential actions and leaves visible evidence. |
| Real modularity | Federation, adapter, CharacterKit, Watchtower, and cloud services retain explicit boundaries. |
| Affirmative identity | The Federation concept is reasserted at architectural decision points. |
| Verifiable work | Tests and checks are evidence; prose cannot substitute for them. |

## Scope rule

The `hackathon` directory is the only repository touched for this endeavor
unless the owner explicitly authorizes a separate external operation. External
systems may be integrated through documented interfaces, but sibling
repositories are not read or modified as ordinary work here.
